 4. 08:10–09:20 — БЛОК 1а: КАРКАС УВЕДОМЛЕНИЙ  (P0)
--------------------------------------------------------------------------------
 ЗАДАЧИ
 1. data/Notifications.kt — LauncherNotificationService
    (NotificationListenerService):
      - onNotificationPosted / onNotificationRemoved;
      - учитывать только пользовательские категории: message, email, call,
        alarm; игнорировать isOngoing без isClearable;
      - счётчик непрочитанных по пакетам, тело уведомления не хранить;
      - onListenerConnected / onListenerDisconnected с переподключением.
 2. Разрешение — только вручную пользователем:
      - строка в настройках «Доступ к уведомлениям» открывает
        Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS;
      - состояние читать через
        NotificationManagerCompat.getEnabledListenerPackages(context).
 3. Мост «сервис → ViewModel»: синглтон-брокер со StateFlow<Map<String, Int>>,
    сервис живёт вне Compose, VM подписывается и кладёт в
    LauncherUiState.badges.
 4. Фича-флаг badgesEnabled, по умолчанию FALSE (как у виджетов):
    выключено — ноль изменений в интерфейсе.

 КРИТЕРИИ ПРИЁМКИ
 - Без разрешения: интерфейс как в 1.4, крашей нет, в настройках «выключено».
 - С разрешением: пришло сообщение — в state.badges ненулевой счётчик пакета.
 - Нагрузка: троттлинг обновлений ~400 мс, никакой работы в onBind сверх
   подписки.

 РИСКИ
 - MIUI / EMUI / One UI убивают listener  → перечитывать
   activeNotifications при ON_START лаунчера, не полагаться на постоянную
   работу сервиса.
 - onNotificationPosted дёргается на прогресс загрузок → троттлинг по
   пакету и сравнение счётчиков перед эмитом.
 - После перезагрузки сервис поднимается системой → проверить, что состояние
   восстанавливается из activeNotifications.

 5. 09:35–10:45 — БЛОК 1б: БЕЙДЖИ И «СЕЙЧАС ИГРАЕТ»
--------------------------------------------------------------------------------
 ЗАДАЧИ
 1. Бейдж-точка: AppIcon / AppTile принимает badgeCount: Int, рисуется
    кружок с цифрой 1–9 или «9+» поверх плитки.
 2. Где показывать: сетка док-панели, закреплённые, недавние.
    В результатах поиска — не показывать.
 3. «Сейчас играет» в скоупе «Сегодня»:
      - MediaSessionManager.getActiveSessions(ComponentName), нужен тот же
        доступ к уведомлениям;
      - карточка под «Батареей»: иконка, трек, исполнитель, play/pause,
        переход в приложение;
      - нет активной сессии — карточки нет (высота не прыгает).
 4. Настройки: две строки — «Значки уведомлений» и «Сейчас играет» плюс
    подсказка, как выдать доступ.
 5. Строки EN и RU в паритете, ключи вида badge_* / now_playing_*.

 КРИТЕРИИ ПРИЁМКИ
 - Точка появляется и исчезает без перезапуска лаунчера.
 - Открыл приложение из уведомления — точка гаснет (onNotificationRemoved
   или клик по иконке).
 - Музыка играет — карточка с рабочим play/pause; пауза и стоп — карточка
   уезжает.
 - Строки настроек честно отражают состояние доступа к уведомлениям.
 - При выключенном флаге лаунчер неотличим от 1.4.

 РИСКИ
 - MediaSessionManager кидает SecurityException без доступа → runCatching,
   карточка просто не рисуется.
 - Плееры отдают пустые метаданные → фолбэк на Notification.extras
   (TITLE / TEXT).
 - Счётчик залипает → полный пересчёт из activeNotifications при ON_START
   и после onNotificationRemoved.

 8. 12:30–13:50 — БЛОК 2: ПЕРЕТАСКИВАНИЕ ИКОНОК И ПАПКИ  (P1)
--------------------------------------------------------------------------------
 ЗАДАЧИ
 1. Перестановка закреплённых плиток (домашний экран и сетка док-панели):
      - долгое нажатие → «подъём» плитки (масштаб + тень), перетаскивание;
      - порядок в prefs (pinned_order); миграция: взять текущий список.
 2. Папки:
      - бросить иконку на иконку → папка из двух приложений, имя «Папка»
        или по первой букве;
      - открытие папки — лист в стиле Ubuntu (заголовок + сетка 3×N);
      - добавление и удаление приложений, пустая папка удаляется сама;
      - папку можно закрепить на домашнем экране как обычную плитку.
 3. Хранение: folders в prefs, JSON: id, name, список ключей приложений.

 КРИТЕРИИ ПРИЁМКИ
 - Перетаскивание не конфликтует со свайпом между скоупами (pager
   блокируется на время drag).
 - Порядок и папки переживают перезапуск и перезагрузку.
 - Удаление приложения из папки не оставляет пустых мест, пустая папка
   исчезает.
 - Перетаскивание можно отменить (отпустить вне цели или кнопка «назад»).

 РИСКИ
 - Жест drag против горизонтального pager → userScrollEnabled = false на
   время drag, порог 8 dp.
 - Папка в папке → запрет: бросок папки на папку игнорируется подсказкой.
 - Битый JSON → чтение в runCatching, некорректные записи отбрасываются
   (как в виджетах).

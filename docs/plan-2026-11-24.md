## 08:10–09:20 — Блок 1а: каркас уведомлений (P0 дня)

### Задачи

1. `data/Notifications.kt` — `NotificationListenerService` (`LauncherNotificationService`):
   - `onNotificationPosted` / `onNotificationRemoved`, только `Notification.CATEGORY_*` из списка
     «пользовательские» (message, email, call, alarm), игнор ongoing/foreground-service без `isClearable`.
   - Считать непрочитанные по пакетам, не хранить тело уведомления дольше, чем нужно.
   - `onListenerConnected` / `onListenerDisconnected` — переподключение.
2. Разрешение даётся пользователем вручную:
   - в настройках строка «Доступ к уведомлениям» → `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`;
   - состояние читать через `NotificationManagerCompat.getEnabledListenerPackages(context)`.
3. Мост «сервис → ViewModel»: синглтон-канал (`StateFlow<Map<String, Int>>` + брокер),
   сервис живёт вне Compose, VM подписывается и складывает в `LauncherUiState.badges`.
4. Фича-флаг `badgesEnabled` (по умолчанию **false**), как у виджетов — выключено = ноль эффекта.

### Критерии приёмки

- Без разрешения: ноль изменений в UI, ноль крашей, в настройках видно «не включено».
- С разрешением: приходит сообщение → в `state.badges` появляется ненулевой счётчик для пакета.
- Потребление: сервис не делает работы в `onBind` сверх подписки; обновления троттлятся (~400 мс).

### Риски и что делать

| Риск | Решение |
|---|---|
| Прошивки (MIUI/EMUI/One UI) убивают listener | Не полагаться на постоянную работу: перечитывать `activeNotifications` при `ON_START` лаунчера |
| `onNotificationPosted` вызывается на каждое обновление прогресса | Троттлинг по пакету, сравнение счётчиков перед эмитом |
| Сервис в отдельном процессе/после ребута | `android:label`, `BIND_NOTIFICATION_LISTENER_SERVICE`; состояние восстанавливается из `activeNotifications` |

## 09:35–10:45 — Блок 1б: бейджи и «сейчас играет»

### Задачи

1. Бейдж-точка на иконке приложения: `AppIcon` / `AppTile` принимает `badgeCount: Int`,
   рисуется маленький кружок с цифрой (1–9, дальше `9+`) поверх плитки.
2. Показывать бейджи в: док-панели (сетка), закреплённых, недавних. В поиске — нет.
3. «Сейчас играет» в «Сегодня»:
   - `MediaSessionManager.getActiveSessions(ComponentName)` (нужен тот же доступ к уведомлениям);
   - карточка под «Батареей»: иконка, название трека, исполнитель, play/pause, переход в приложение;
   - нет сессии → карточки нет (высота не «прыгает», просто отсутствует).
4. Настройки: две строки — «Значки уведомлений» и «Сейчас играет» + подсказка, как выдать доступ.
5. Строки EN/RU в паритете.

### Критерии приёмки

- Точка появляется/исчезает без перезапуска лаунчера.
- Открыл приложение из уведомления → точка гаснет (по `onNotificationRemoved` или по клику).
- Музыка играет → карточка с play/pause работает; пауза/стоп → карточка уезжает.
- Настройки-строки честно отражают состояние доступа к уведомлениям.
- Всё это — при включённом флаге; при выключенном лаунчер выглядит как 1.4.

### Риски и что делать

| Риск | Решение |
|---|---|
| `MediaSessionManager` кидает `SecurityException` без доступа | `runCatching`, карточка просто не рисуется |
| Разные плееры отдают пустые метаданные | Фолбэк на `Notification.extras` (TITLE/TEXT) |
| Счётчик «залипает» | Пересчёт из `activeNotifications` при `ON_START` и после `onNotificationRemoved` |

## 12:30–13:50 — Блок 2: drag-перестановка и папки (v1.6)

### Задачи

1. Перестановка закреплённых плиток на домашнем экране и в сетке док-панели:
   - долгое нажатие → «подъём» плитки (scale + shadow), перетаскивание, авто-скролл не нужен;
   - порядок хранить в prefs (`pinned_order`), миграция со старого списка — просто взять текущий.
2. Папки:
   - бросить иконку на иконку → папка из двух приложений, имя «Папка» (или по первой букве);
   - открытие папки — лист в стиле Ubuntu (заголовок + сетка 3×N);
   - добавление/удаление приложений из папки, папка без содержимого удаляется сама;
   - папка может быть закреплена на домашнем экране как обычная плитка.
3. Хранение: `folders` в prefs JSON (`id`, `name`, список ключей приложений).

### Критерии приёмки

- Перетаскивание не конфликтует со свайпом между скоупами (pager блокируется на время drag).
- Порядок и папки переживают перезапуск и перезагрузку.
- Удаление приложения, лежащего в папке, не оставляет «дырку» (папка чистится, пустая исчезает).
- Drag можно отменить (отпустить вне цели / кнопка «назад»).

### Риски

| Риск | Решение |
|---|---|
| Жест drag против горизонтального pager | `userScrollEnabled = false` у pager на время drag; порог 8 dp |
| Папка внутри папки | Запрет: бросок папки на папку игнорируется с подсказкой |
| Потеря данных при кривом JSON | Чтение через `runCatching`, как в виджетах; битые записи отбрасываются |
